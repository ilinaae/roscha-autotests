# UI-автотесты интернет-магазина «Роща»

Целевой сайт — `https://roscha.net/`. Сценарии составлены по отчёту «Функциональное тестирование интернет-магазина „Роща“», разделы 6.2 и 6.4, и заданию `automation-spec.pdf`.

В проекте 10 проверок авторизации и один сквозной сценарий. Сквозной тест заканчивается на странице оформления, по условию работы. Все проверки входа проходят через парольную форму существующего аккаунта. Регистрация, SMS, звонок и сторонние платформы за пределами этого набора.

## Запуск на Windows

Из папки `roscha-autotests` установи зависимости. Проверено с Python 3.11, Chromium, Playwright 1.65.2, pytest 9.2.0, Allure Pytest 2.16.2 и Allure CLI 2.46.1. Для команды `npx.cmd` нужны Node.js и Java. Можно использовать уже установленный Python или создать отдельное окружение.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
```

В `local.json` заполни `account` данными существующего аккаунта. Если файла нет, скопируй `local.example.json`. Это локальный файл, который не нужно прикладывать к заданию. В каталоге выбери имеющийся в продаже штучный товар без вариантов или с заранее известным вариантом. Запиши его точное название, артикул, цену и единицу измерения.

| Поле | Что указать |
|---|---|
| `account.email`, `phone`, `login`, `password` | Email, телефон, отдельный логин и пароль своего аккаунта. Телефон указывается в формате, который принимает парольная форма. |
| `account.marker` | Значение, по которому можно узнать свой аккаунт. По умолчанию тест сверяет `account.email` с полем email на `/personal/private/`. После смены адреса проверь, какой email сохранён в «Персональных данных». Для другого признака укажи маршрут `paths.profile` и CSS `selectors.account_marker`. |
| `product.query`, `name`, `article` или `id` | Запрос, полное название и артикул. Если артикул в карточке не показан, укажи ID из атрибута `data-product-id` кнопки добавления в корзину. |
| `product.price`, `unit`, `variant` | Цена в рублях, например `93.00`, и единица, например `шт.`. `variant` заполняется, если нужно сверять вариант товара. |
| `base_url`, `timeout_ms`, `navigation_timeout_ms` | Адрес сайта и тайм-ауты ожидания в миллисекундах. |

Также поддерживаются переменные `ROSCHA_EMAIL`, `ROSCHA_PHONE`, `ROSCHA_LOGIN`, `ROSCHA_PASSWORD`, `ROSCHA_MARKER`, `ROSCHA_BASE_URL` и `ROSCHA_CONFIG` для пути к локальному JSON. Переменные имеют приоритет над файлом.

```powershell
.\.venv\Scripts\python.exe -m pytest --collect-only -q
.\.venv\Scripts\python.exe -m pytest --headed --browser chromium
```

Для запуска только входа добавь `-m auth`, для сквозного сценария — `-m e2e`. Уровень логов задаётся через `--log-cli-level=DEBUG`, `INFO`, `WARNING` или `ERROR`.

Если VPN мешает открыть «Рощу», в Windows можно направить Chromium к сайту через Wi-Fi. Используй `--wifi-interface auto`: pytest найдёт подключённый беспроводной адаптер, даже если его индекс изменился после перезагрузки. При нескольких адаптерах можно посмотреть индексы командой `Get-NetAdapter -Physical` и указать нужный индекс вместо `auto`.

```powershell
python -m pytest --wifi-interface auto --headed -m auth
```

Режим действует только для браузера тестов. Он открывает HTTPS к домену магазина через выбранный интерфейс и закрывает локальный прокси после прогона. Другие домены в этом режиме блокируются.

## Состав проверок

| ID | Входные данные | Ожидаемый результат | Связь с отчётом |
|---|---|---|---|
| `AUTH-P01` | Email и верный пароль | Открывается личный кабинет нужного покупателя | ТК-А09, ФТ-А08 |
| `AUTH-P02` | Телефон и верный пароль | То же, через парольную форму для телефона | Вариант ТК-А09, ФТ-А08 |
| `AUTH-P03` | Логин и верный пароль | То же, по отдельному логину | ТК-А09, ФТ-А08 |
| `AUTH-N01` | Пустой идентификатор, верный пароль | Ошибка обязательного поля, пользователь остаётся гостем | Дополнение к ФТ-А08 |
| `AUTH-N02` | Email, пустой пароль | Ошибка обязательного поля, пользователь остаётся гостем | Дополнение к ФТ-А08 |
| `AUTH-N03` | Неполный телефон, верный пароль | Неверный формат или отказ по идентификатору, пользователь остаётся гостем | ФТ-А08, класс неполного телефона из ТК-А03 |
| `AUTH-N04` | Несуществующий email, верный пароль | Ошибка входа, пользователь остаётся гостем | Дополнение к ФТ-А08 |
| `AUTH-N05` | Email, неверный пароль | Ошибка входа, пользователь остаётся гостем | ТК-А10, ФТ-А08 |
| `AUTH-N06` | Телефон, неверный пароль | Ошибка входа, пользователь остаётся гостем | Вариант ТК-А10, ФТ-А08 |
| `AUTH-N07` | Логин, неверный пароль | Ошибка входа, пользователь остаётся гостем | ТК-А10, ФТ-А08 |
| `E2E-01` | Email и пароль, один доступный товар | Вход, поиск, карточка, сверка корзины и состава на оформлении | ТК-А09, ТК-М02, ТК-М09, ТК-М11, ТК-М19 |

Семь негативных вариантов задаются через `pytest.mark.parametrize`. У каждого свой ID в списке pytest и Allure. Перед каждым тестом создаётся чистая браузерная сессия, поэтому вход в обычном браузере можно сохранить. Сквозной тест требует пустой корзины аккаунта. После проверки удаляется добавленная строка, если у неё то же количество. При сбое очистки pytest показывает ошибку, тогда стоит проверить корзину вручную.

## Локаторы и результаты

`core` содержит конфигурацию и диагностику, `ui` — CSS-локаторы, Page Object и `BaseElement`, `autotest` — сценарии и параметры. Тесты ждут конкретных элементов и результатов. Кейс проверяет видимую ошибку входа, затем открывает личный раздел и проверяет, что он требует авторизации.

На гостевой странице входа тест нажимает «Войти с помощью пароля» и ждёт появления поля пароля. Начальные локаторы находятся в `ui/selectors.py`. Для переопределения скопируй нужный ключ в `selectors` в `local.json` и укажи CSS на наблюдаемый элемент. При сбое `logged_in` укажи видимый признак авторизованной сессии, при `account_marker` — область с данными профиля. В `errors` можно задать регулярные выражения для классов `required`, `phone_format` и `credentials` по сообщениям сайта. Если в формах появится CAPTCHA, действует условие замены сайта из задания. Доступность входа по телефону с паролем и отдельному логину нужно подтвердить при прогоне.

При ошибке Allure показывает шаг и имя локатора, безопасный лог и скриншот. Из скриншота скрываются текст, поля, изображения и встроенные виджеты, чтобы не показать контакты и секреты. Если снимок сделать нельзя, сохраняется причина. Отсутствие тестовых данных отмечается как `skipped`.

## Автоматические отчёты Allure

После прогона pytest сам собирает HTML и печатает путь к `index.html`. На каждый запуск создаётся одна папка, например `reports/2026-11-23_15-30-00/`. Время в имени берётся из настроек компьютера. Отчёт создаётся и при падении теста. Режим `--collect-only` только показывает список тестов.

Чтобы открыть папку с отчётами, выполни `Invoke-Item .\reports` и выбери `index.html` в папке нужного запуска. Можно также открыть путь, который pytest напечатал после сводки. Для сборки HTML требуются Node.js с `npx` и Java. Если Allure не смог собрать HTML, pytest покажет причину и путь к сохранённым данным прогона внутри папки с датой.

В обычной команде флаг `--alluredir` больше не нужен. Если явно указать его для выгрузки исходных результатов, эти файлы сохранятся по указанному пути, а HTML всё равно будет в `reports/`.
